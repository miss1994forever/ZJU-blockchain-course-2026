# 实现说明与需求对应

## 设计边界

本项目在助教提供的 Hardhat + React/TypeScript 框架上实现。使用本地链、普通 ERC20、Uniswap V2 风格的全价格区间恒定乘积模型。流动性凭证使用课程要求的 ERC721，不实现 V3 集中流动性或 V4 Hooks。

- `TestToken.sol`：两种 18 位小数的教学代币，每次水龙头为调用者铸造 10,000 枚。开放增发仅用于本地测试。
- `MiniDEX.sol`：每次部署即一个独立交易所，一个交易所支持多个不同代币对的池。代币地址排序后去重。创建池不等于添加初始流动性。
- `AtomicArbitrage.sol`：由调用者提供本金，在同一笔 EVM 交易内先买入中间代币，再在另一个池卖出，要求最终输出覆盖本金和最低利润。本项目实现两个交易所之间同一代币对的套利；不实现同所三角套利。

## AMM 与手续费

输入 `dx`、储备 `x,y`、费率 30 bps 时：

```text
dxWithFee = dx * 9970
dy = floor(dxWithFee * y / (x * 10000 + dxWithFee))
xNew = x + dx
yNew = y - dy
```

0.30% 手续费全部留在池子储备，不再另设协议手续费。交易后 `k` 增长，每份既有流动性对应的储备价值随之增加。手续费在撤回时随对应份额兑现。

这是一种课程允许的自定义分红机制。**不能把撤回的两种币分别减去初始投入，直接标注为手续费收益**：价格变化与无常损失也会改变两币数量。页面显示初始投入与当前可赎回额，并准确说明包含手续费。

## NFT 与份额

- 首笔流动性总份额 `floor(sqrt(a*b))`，其中 1,000 个最小份额单位永久锁定，剩余铸为 NFT 对应份额。
- 后续添加按当前储备比例取用用户填写的最大金额，多余金额不转入合约。
- 新份额 `min(a*totalShares/reserveA, b*totalShares/reserveB)`，向下取整。
- 每次添加产生独立 NFT，记录池编号、份额、两币实际投入、时间、原始提供者；`tokenURI` 为链上 Base64 JSON 元数据。
- NFT 支持 ERC721 标准转移。赎回权跟随当前 NFT 所有者；只允许所有者销毁，获批 operator 不可自行赎回。
- 销毁时提取 `shares/totalShares` 比例的当前储备；NFT 随之失效，历史 position 记录保留供追踪。
- 前端展示活跃 NFT 的最初提供者、现持有人、投入、份额及时间。烧毁事件和历史添加/移除事件可供链上审计。

## 套利

链下搜索负责发现路线，链上合约保证执行的原子性。两次独立钱包交易不能满足原子套利要求。本项目的 `execute` 只发出一笔交易，其中包含两次 DEX 调用；第二次输出不足时 revert 会恢复第一次的池储备、余额及授权状态。

不需要闪电贷即可实现原子性。本金来自调用者，获利和本金在同一交易中回到调用者。报告中的利润已扣除两笔 DEX 手续费，**未扣除以 ETH 支付的 Gas**；不同计价资产不能无汇率地相减。报告单独记录 gasUsed。

- 前端搜索双方向、双基础币及一组离散本金。
- 脚本扫描双方向、双基础币的 1–300 整数本金，选择搜索范围内报价利润最高的路线。
- 两个工具均不声称找到了任意市场条件下的全局最优金额。
- 为可复现演示，脚本先通过普通交易制造价差，再自动检测并套利。

## 测试与限制

合约包含重入保护、SafeERC20、交易截止时间、最低输出和最低赎回量检查，储备上限 uint112；收费转账代币被入账差额检查拒绝。前端支持普通 18 位小数 ERC20。重基代币、回调型非标准代币等不在支持范围内。本项目用于教学，未进行生产审计。

20 个本地测试账户由开发节点预先分配测试 ETH，前端与脚本为每个调用者分别领取 ERC20。随机模拟具有固定伪随机种子，报告包含交易哈希、地址与最终储备检查。
